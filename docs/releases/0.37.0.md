Coding agents get two commands for their own project: `ddc agent footprint` says what its checkouts and worktrees hold, and `ddc agent clean` removes its safe build caches, but only after you allow it. You switch that with `ddc settings set` or in the app's Settings. The Review window now also says what Docker Desktop's disk image holds before you clean it.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.37.0/DISCLAIMER.md).

**One project's footprint: `ddc agent footprint`**

- Give it any folder of a project, the main checkout or a worktree. It finds the main checkout, asks git for every worktree, and walks only those, with the same rules as `ddc scan`. It answers in seconds, takes no lock, saves no report and removes nothing.
- Each worktree is in one place: selected now; after its session ends (locked by a live session, in use, or used within `--worktree-min-age`); or held back, with the reason (uncommitted changes, ignored content of its own, commits of its own, and so on). The totals keep `safe` apart from `rebuildable`.
- It ends with the `ddc clean` of the main checkout. Outside a git repository, or when the main checkout is your home folder, it exits 2. `--json` follows `docs/footprint.schema.json`.

**A coding agent's cleanup: `ddc agent clean`**

- It removes only the `safe` project artifacts (`__pycache__`, `.pytest_cache` and the like) inside one project's checkouts. It never removes a `.venv`, a worktree, a tool's command, or anything outside the project, such as `~/.cargo` or another project.
- It does this only while `settings.json` has `agents_clean_safe` on, which is off by default. Without it, with `--dry-run`, or when the settings cannot be read, it removes nothing, takes no lock and writes no journal line.
- What only you can clean there (an idle `.venv`, a dead worktree, and the safe items while the setting is off) it lists for you, with a `ddc clean --items -` command that carries the list in a heredoc. Read it, then run it yourself.
- A real run takes the lock a clean takes (`ddc lock status` names `agent clean`), checks each item again as any clean does, and writes `consent: agent` and the project in every journal line. `--items` only narrows it. `--json` follows `docs/clean.schema.json`.

**Letting agents clean: `ddc settings set` and Settings → Automation**

- `ddc settings set agents_clean_safe on` switches it on. At a terminal it first says what it allows and links the disclaimer, then asks, default No. Without a terminal it is refused, so an agent's command alone does not switch it on. `off` never asks.
- In the app: Settings → Automation → Coding agents, "Let coding agents clean safe items". The toggle runs the same command and shows what the file says. While it is on, the popover says "Coding agents may clean safe items".
- Each change writes one `settings-set` line to the action journal. It takes no lock a scan or clean takes, so it never waits for one.
- The app and `ddc` now hold a small lock file, `settings.lock`, while they write `settings.json`, so neither loses the other's change. The file keeps its permissions.
- While the setting is on, a `ddc` older than this release refuses `settings.json` and names the key. Update it, or switch the setting off.
- `ddc agent status` says whether it is on.

**Docker Desktop.** The Review window's Docker Desktop item now asks Docker what its disk image holds: images, containers, volumes and build cache with their sizes, and about how much a clean frees. The Clean sheet counts that estimate once Docker answered. After a clean, the result shows what Docker said it reclaimed. `ddc disk docker [--json]` gives the same answer in a terminal (`docs/docker.schema.json`). Docker Desktop must be running.

**Fixes.** The Gate's dependency check failed on RUSTSEC-2026-0486 (rustix 1.1.5, its xattr functions); ddc calls none of them, and rustix is now 1.1.6.

**Windows (not released yet).** The Windows port gained its own protected folders in the home (AppData, the browsers' profiles, OneDrive and others) and the system folders Windows reports. Windows builds still refuse to scan or clean until the port is done.

**Report schemas.** New: footprint 1 (`docs/footprint.schema.json`), docker 1 (`docs/docker.schema.json`). Clean 13 (`not-consented`, `agent-opt-in-off`, and the agent fields), journal 14 (the agent fields and the `settings-set` kind), progress 11, lock 2 (the holder `agent-clean`), error 5 (`not-a-repository`, `home-is-the-checkout`). Settings stays 1 with the new key `agents_clean_safe`, and agents stays 1 with the new field `agents_clean_safe`. Scan is unchanged.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below. If you upgrade with Homebrew while the app is quit, open it once so it registers its scheduled scan again.
