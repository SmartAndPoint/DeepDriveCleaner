The clean now asks the Trash before each move and reports what a Recycle Bin refuses or destroys. This prepares the Windows Recycle Bin; on macOS and Linux nothing changes for you.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.33.0/DISCLAIMER.md).

- **The Trash is asked first.** Before each move, and in `clean --items --dry-run`, ddc asks the Trash whether it takes the item. A coding agent's session is asked once for all its parts, before the first one moves, so a session the Trash cannot take is skipped whole instead of half moved. On Linux this also means a session on a filesystem with no usable Trash is now skipped, where before its companions moved first and the session failed.
- **New skip reason `recycle-bin-refuses`**, with a `cause`: `no-bin`, `too-large`, `bin-full`, `nuke-on-delete`, `no-recycle-files`, `path-refused`, `settings-unreadable` or `would-destroy`. Each message names `--permanent`; `bin-full` also says to empty the Recycle Bin. The Recycle Bin's free room is a budget for the whole run, so the dry run and the clean refuse the same items. Only Windows will give this reason, once it is supported.
- **New outcome `removed-not-recycled`**: the item is gone and is not in the Recycle Bin. Its space is freed, so it is not counted as failed and leaves the saved report as a deleted item does, but `ddc clean` exits 1 and prints it on a line of its own.

**Report schemas.** Clean 11 and journal 11 (the new reason and outcome), progress 9. Update the app and the CLI together; the scan report stays at 8.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
