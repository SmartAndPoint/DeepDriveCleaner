A Windows-only step: the Windows port can now read a folder. Nothing changes on macOS or Linux.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.17.5/DISCLAIMER.md).

- **Windows: the directory reader.** A folder is read through its own handle, many entries per call, past the 260-character path limit. A link (a symlink, a junction, any name surrogate) is listed as a link and never followed. A volume mounted into a folder is a boundary: the scan does not enter it. On a file system without file ids (FAT, exFAT) the reader falls back to a slower listing that opens each entry for its id, and still tells links apart.
- **Windows: hard links counted once.** A Windows folder listing does not carry a file's link count. So a file with allocated bytes goes into the scan's hard-link table, and a file that several names share counts once, as on macOS and Linux. pnpm and uv store their packages this way.
- Windows is still unsupported: `ddc` there runs only `--version`, `--help` and `rules`.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
