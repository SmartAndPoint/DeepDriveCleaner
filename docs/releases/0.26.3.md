A Windows step on the way to Windows support: ddc can now see which of your programs use a folder. Windows is still not supported, so nothing of this runs outside the tests yet. On macOS and Linux nothing changes.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.26.3/DISCLAIMER.md).

- **Windows: the in-use check reads your processes.** Before a clean, ddc skips an item that one of your programs uses: its program file, its working folder, an argument or its `VIRTUAL_ENV` or `CONDA_PREFIX` lies inside the item. On Windows ddc now reads all of this for each of your processes, the same as it does on Linux. Paths are compared without regard to upper or lower case or to `/` and `\`. A path on a network share named in a command line is never opened.
- **What it cannot read, it says.** A process ddc cannot read in full is counted, as on macOS and Linux. That includes a protected one and a 32-bit one, whose working folder Windows keeps where ddc does not read it yet. Programs loaded as modules (a DLL, a `.pyd` or `.node` file inside a folder) come in the next step.

**Report schemas.** None change.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
