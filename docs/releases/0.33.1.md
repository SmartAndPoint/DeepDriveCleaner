On Linux, ddc never opens a special file, an odd name survives the suggested clean command, and a Trash folder that stays open to others is refused.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.33.1/DISCLAIMER.md).

- **Special files are never opened.** A FIFO, a socket or a device node inside a finding is counted at 0 bytes and removed by a rename or an unlink, never read. A marker file such as `pyvenv.cfg` or `.git` is now read only when it is a regular file. A symlinked marker, or a device under a marker's name, reads as absent. Before, a symlink to a device was followed. This applies on macOS too.
- **Pins fail closed.** A toolchain pin that exists but cannot be read, or that is a symlink, keeps every version of its tool. This covers `~/.pyenv/version`, `~/.rustup/settings.toml`, `~/.nvm/alias/*` and a project's `.python-version`, `.nvmrc` or `rust-toolchain`. Before, a symlinked pin was skipped, and with pyenv the global Python could become a finding.
- **Odd names.** A newline or a tab in a path now stays literal inside the quotes of the suggested `ddc clean` command, so pasting it into `sh` names the same path. For other control characters, and for names that are not UTF-8, no command is suggested, only a sentence. The background log escapes such names.
- **Long names.** An item whose name is close to 255 bytes can be cleaned again: its tombstone name is cut on a character boundary, shorter again where the filesystem allows less (eCryptfs).
- **The Trash on exFAT, FAT and other filesystems that ignore `chmod`.** A `.Trash-<uid>`, `files/` or `info/` that stays open to group or others after ddc sets it to 0700 makes the move refuse as `trash-crosses-filesystem`, naming `--permanent`. The dry run says so first. Your own `files/` and `info/`, if open to others, are set to 0700, in the home Trash too.
- Sparse files are reported at their allocated size by `scan`, `du` and `clean`, as before; there is now a test for it.

**Report schemas.** None change.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
