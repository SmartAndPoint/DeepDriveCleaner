`ddc` now removes a coding agent's dead worktree, through `git worktree remove` and nothing else, after checking all six conditions again right before it. 0.18.1 and 0.18.2 were not released on their own; this release carries them: on Linux a clean stays on the scanned mount, a scan never hangs on a pipe where a small file should be, and the Windows port reads real hard-link counts.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.19.0/DISCLAIMER.md).

- **Dead agent worktrees are selected.** A Claude Code worktree that passes the six conditions of 0.18.0 is `rebuildable` and selected, and counts in the "can free" totals. `ddc clean --yes --class rebuildable` removes it with `git -C <main checkout> worktree remove <path>`. Its branch is kept: `git branch -d` drops it when you want.
- **Only git removes a worktree.** No `--force`, no `git worktree prune`, never a plain delete or a move to the Trash. Before the command, the clean asks git to list the main checkout's worktrees and finds this one by its file identity, not by how its path is spelled. If git does not list it, nothing runs and the item is skipped as "no git lists this folder". Another worktree's administrative folder is never touched, even when that worktree was moved away.
- **The conditions are checked again at the clean.** Between the scan and the clean a worktree can be locked, used, get an initialized submodule, an edit, an ignored file of its own or a new commit. Then it is skipped with the new reason `worktree-kept`, which names the condition and why. A git that fails or hangs keeps the worktree too.
- **Your own worktrees, by list.** A worktree you made yourself (`git worktree add`), or one used an hour ago, is never selected. When you list it (`clean --items`, the app's sheet) or confirm it in the terminal, it is removed. Doing that waives "made by an agent" and "idle", never the rest: a listed worktree with uncommitted work, unique ignored files, an initialized submodule or a commit only it holds is refused as `worktree-kept`, in the dry run already.
- **An exclusion inside a worktree keeps it.** As for any finding, an `--exclude` or a settings exclusion below a worktree protects the whole worktree, since `git worktree remove` would take the excluded folder with it.
- **What is inside goes with it.** A `.venv` or `node_modules` inside a selected worktree is not removed twice: the plan leaves it out and the worktree counts its bytes once. Listing a worktree and something inside it skips the inner item as `inside-another-item`.
- **An orphan worktree** (its repository is gone) goes to the Trash when you list it, or is deleted with `--permanent`.
- **Linux: the clean stays on the scanned mount (0.18.1).** Before it moves or removes anything, the clean opens the item's folder relative to the scan root with `openat2`. A bind mount, any other mount, or a symlink on the way is refused as `parent-changed`; a mount at the item itself is `incomplete`; a scan root renamed away and replaced during a clean is refused. Kernels without the mount id in `statx` read it from `/proc/self/fdinfo`; where no mount id can be read at all, the clean refuses.
- **A FIFO no longer hangs a scan (0.18.2, macOS, Linux).** The few small files the scan reads (a venv's `pyvenv.cfg`, a worktree's `.git` file, `CMakeCache.txt`) are opened without blocking and read up to 4 MiB; a FIFO with that name reads as nothing.
- **Windows (0.18.2).** Those reads never download a OneDrive-style placeholder and refuse a link. Each file with allocated bytes gets its real hard-link count, so a file whose other link lies outside the scan counts as shared, not freed. Windows is still unsupported: `ddc` there runs only `--version`, `--help` and `rules`.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below. The clean report and the action journal are now schema version 7, the progress events version 5, for the skip reason `worktree-kept`; the app reads them. The scan report did not change.
