A keep marker counts in any letter case, and the checks before a clean find it where the scan does.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.34.1/DISCLAIMER.md).

- **`.ddc-keep` in any case.** A `.DDC-KEEP` or `.Ddc-Keep` now keeps its folder like `.ddc-keep`, in the scan, in the dry run and in the checks before each removal: inside an item, at its top and in a folder above it. Before, the name was compared byte for byte, so on a case-insensitive folder (ext4 with casefold, exFAT) a marker below an item's top was missed, and on a case-sensitive disk a marker made after the scan in another case was missed by the clean. A folder that cannot be listed while ddc looks for a marker counts as kept.
- **`ddc keep remove` names the real marker.** It still removes only a file named exactly `.ddc-keep`. When the folder holds a marker in another case, it now fails and names that file, so you know what still protects the folder. Before, it said there was no marker while the folder stayed protected. Remove Protection in the app shows the same message.
- **Protected folders and rule names.** A protected folder named in another case (`~/DOCUMENTS` for `~/Documents`) is refused as before; there are now tests for it on casefold ext4 and exFAT. Rule names match byte for byte on every filesystem: a `Node_Modules` folder is not a `node_modules` finding.
- On Linux, `Cache` and `cache`, or a name and its other Unicode form, are two folders and are counted as two.

**Report schemas.** None change.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
