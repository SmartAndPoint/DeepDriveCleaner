When a clean or a scan cannot start because another one holds the lock, the app and `ddc` now say which one it is, and offer to stop it or to wait for it. After an update, the popover says which version made the last scan instead of "No scan yet".

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.36.0/DISCLAIMER.md).

**Who holds the lock**

- **In the app.** When the Review sheet's check, its Clean, or Scan now meets a scan or clean that is already running, the app names it, for example "A clean started from a terminal 3 min ago (pid 4101), on item 4 of 8", and says what Stop does ("Stop ends it after this item"). Each holder gets a Stop, and there is one Wait. With no holder named, there is only Wait.
- **Stop** interrupts that one process, as Ctrl-C at its terminal would. A clean finishes its current item and runs no other; a scan, a dry run or `keep remove` ends at once; `disk free` stops before its next action. The app shows "Stopping…" until it is gone. It never sends SIGKILL.
- **Wait** starts what met the lock once nothing blocks it. On the sheet, Wait is consent to clean the same items while the sheet stays open: closing the sheet, Stop Waiting, or any change to the list ends it. If the run meets the lock again, the app waits again, 15 seconds at the least.
- **A Clean that met the lock** no longer ends the sheet. The sheet stays, and it says that the clean did not start and nothing was touched.
- **`ddc lock status [--json]`** lists the holders: pid, command, start, whether it was started from a terminal or the app, and for a clean its phase and progress. Each holder writes a small record next to the lock while it holds it (`lock.holders/`). A holder that was killed leaves its record, and the next one removes it.
- **`ddc lock stop --pid P --started T`** sends SIGINT and nothing else. It sends it only when that pid still holds the lock, started at `T`, is yours and runs ddc's own binary. Otherwise it exits 2 and sends nothing.
- **A command that meets the lock** still exits 75, and now names the holders after its `ddc:` line. With `--json` it prints the error report with the code `busy` and the holders, as 69 already did. The background scan still skips and exits 0.
- A `ddc` from before this release writes no record. While you upgrade, a lock it holds is named by nobody.

**After an update.** When the saved scan is of an older format, the popover no longer says "No scan yet" as on a first launch. It says "Your last scan was made by ddc 0.35.0. After the update, this version reads reports differently, so it needs a new scan.", with Scan Now; the header reads "Last scan by ddc 0.35.0 · scan again"; the icon shows no warning. A report made by a newer `ddc` (a Homebrew CLI, say) gets its own words and keeps the warning. Without Full Disk Access, Open Privacy Settings stays the main action, as on a first scan. The Whole Disk view says the same about an older whole-disk report. With scheduled scans on and not paused, the scan after an update (0.35.0) still runs by itself.

**Protected folders.** The list of protected folders is now closed under their parent folders on every OS, so a rule can never claim a folder that holds a protected one. On macOS and Linux every such parent was listed already: nothing changes there.

**Windows (not released yet).** The Windows port gained the Recycle Bin through the shell, checked before and after each move, and protection of `APPDATA` and `LOCALAPPDATA` wherever they point. Windows builds still refuse to scan or clean until the port is done.

**Report schemas.** New: lock 1 (`docs/lock.schema.json`). Error 3 (the `busy` code with `holders`). Scan, clean, journal and progress are unchanged.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below. If you upgrade with Homebrew while the app is quit, open it once so it registers its scheduled scan again.
