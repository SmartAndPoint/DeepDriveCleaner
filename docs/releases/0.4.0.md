The whole startup disk, the coding agents on it, and freeing two areas with their own tools.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.4.0/DISCLAIMER.md).

- **Whole disk.** A new window, opened from the popover ("Where Does the Rest Go?") and shown in the Review window, measures the whole startup disk, not only the home folder. It shows the disk as one bar and has a row per area: Applications, the shared Library, macOS's downloaded data, Homebrew, Conda, `/usr/local`, simulator runtimes, temporary folders, the sleep image and the other users. Each row says what it is and what frees it. **Not counted** shows what macOS uses that no folder accounts for. Stop keeps what was measured so far.
- **Coding agents.** The Whole disk view lists what Claude Code, Codex, Cursor and opencode keep under your home folder: their folders and sizes, their live sessions and how many transcripts of ended ones they keep. It reads session records' named fields, file names and sizes only, never a transcript's content, and it removes nothing.
- **Free space with the owning tool.** Two rows of the Whole disk view now have a button:
  - **Delete Runtime…** on a simulator runtime runs `simctl runtime delete`. It is offered only for a runtime under `/System/Library/AssetsV2` that macOS says can be deleted and that no simulator is using. The runtime does not go to the Trash. If it is the runtime of an installed Xcode's SDK, Xcode downloads it again (several GB) at the next build for it.
  - **Clean Up Homebrew…** runs `brew cleanup` with `HOMEBREW_NO_AUTOREMOVE=1`. It removes old versions in `/opt/homebrew/Cellar` and old downloads in `~/Library/Caches/Homebrew`, and uninstalls nothing.

  Each button first shows the tool's own dry run and the exact command, and runs only after you confirm. Afterwards the row says what was freed, measured, not assumed. When a tool needs an administrator, the sheet gives the command to paste into Terminal; DeepDriveCleaner never asks for a password. Nothing scheduled runs these actions.
- **For scripts.**
  - `ddc disk` prints the whole-disk table, or `--json` with [`docs/disk.schema.json`](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.4.0/docs/disk.schema.json), and saves `last-disk.json`.
  - `ddc disk agents [--json] [--no-sizes]` lists the coding agents ([`docs/agents.schema.json`](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.4.0/docs/agents.schema.json)).
  - `ddc disk free` asks at a terminal for each action, with `--dry-run` for the tools' own dry runs; the app passes its confirmed list with `--actions` ([`docs/disk-free.schema.json`](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.4.0/docs/disk-free.schema.json)).
  - `actions.jsonl` lines carry a `kind` and the journal has its own schema version, now 2. The scan report keeps version 1.
- **Fixes.**
  - Scans of large folder trees no longer slow down quadratically.
  - Settings no longer shows the disabled "Clean download caches automatically" choice; DeepDriveCleaner does not clean on its own.
  - `brew uninstall --zap` also removes the fallback scheduler agent that 0.3.0 may have registered.

**Upgrading.** Run `brew upgrade --cask deepdrivecleaner`. The upgrade quits the app; it opens again at your next login if Open at login is on, or when you open it. Do not upgrade while the app is cleaning.

How it was built, decision by decision, is public too: [DeepDriveCleaner-projectstore](https://github.com/SmartAndPoint/DeepDriveCleaner-projectstore).
