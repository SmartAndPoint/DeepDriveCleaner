On Linux a scan now stays on one mount, and `curl -fsSL https://ddc.sh/install.sh | sh` installs the CLI on macOS and Linux. 0.16.5 to 0.17.3 were not released on their own; this release carries them.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.17.4/DISCLAIMER.md).

- **One-line install, served by ddc.sh.** `curl -fsSL https://ddc.sh/install.sh | sh` now runs the install script, as plain text, instead of the page. It installs `deepdrivecleaner` and `ddc` into `~/.local/bin` on macOS and Linux, checks the archive against `SHA256SUMS`, and never uses sudo. Run it again to upgrade. The CLI page of ddc.sh shows Linux as released, with the x86_64 and ARM64 archives. It was tested on two Linux machines, x86_64 and ARM64.
- **Bind mounts.** A bind mount of the same filesystem has the same device number. Before, the scan entered it, counted it and could find caches inside it, and a clean could then delete through the bind mount into a folder outside the scanned root. Now a bind mount, or any other mount the device number does not show, is skipped as `other-filesystem` and never opened. A file bind-mounted into a folder is skipped too.
- **Automount points.** An autofs direct map, or an NFS or SMB referral, is skipped as `automount`, and the scan never triggers it. Before, the scan stat'ed each entry in a way that mounted it, and could hang on a server that does not answer.
- **Opened beneath the scan root.** Every folder opens relative to the scan root with `openat2`, so a mount or a symlink on the way is refused, not crossed. On a kernel without `openat2`, the folder opens by path and its mount is checked.
- **A finding with such a folder inside is incomplete**, and a clean refuses it.
- `ddc du` can now be lower than `du -skx` by a bind mount's size, because `du -x` enters a bind mount.
- CI tests all this on a real bind mount and a real autofs map.
- The decision is the vault's safety ADR, amendment of 2026-11-01.
- **Windows: one canonical path (0.16.6).** Every part of ddc resolves a path through one call. On Windows it gives `C:\…`, not the `\\?\C:\…` form Windows' own call returns, so an exclude, a skip or a root compares with what the scan finds. A name that the plain form cannot spell (a trailing dot or space, a device name such as `NUL`) keeps the long form and is never matched by mistake.
- **Windows: paths compared without case (0.16.6).** The rule catalog and the protected folders compare Windows paths by one key that ignores case and treats `/` and `\` alike, as Windows does. On macOS and Linux a path is compared as it is, as before.
- **0.16.5.** The popover's scan count test waited for the first of three walk events' file counts, while the popover keeps the largest; it now waits for the largest count.
- **Windows (0.17.1, 0.17.2): one call for a file's identity, links and size.** Every part of ddc reads a file's identity, hard-link count and allocated size through one call per platform, which Windows can answer too. On macOS and Linux the numbers are the same `stat` fields as before (0.17.1).
- **Windows reads them from the file's own handle.** The identity is the volume and the file id; the links and the size come from the same open file, also past the 260-character path limit. A file system whose ids do not fit, or that gives none, is refused rather than guessed, so nothing on it can be planned by mistake.
- **Windows (0.17.4): changes only inside a verified folder.** The Windows port gets the operations a clean is built on: a folder is opened by its own handle and never through a link; an item is opened by name relative to that folder, so a link is the link, never its target; a rename stays inside the verified folder and never replaces another name; a delete never touches a folder. A name with a separator or a `:` (an NTFS stream) is refused. Windows is still unsupported.
- Windows is still unsupported: `ddc` there runs only `--version`, `--help` and `rules`.

**Report schema.** The scan report moves to schema 5, with the new skip reason `automount` (0.17.0). Update the app and the CLI together: an older app shows a report of the new version as one it cannot read.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
