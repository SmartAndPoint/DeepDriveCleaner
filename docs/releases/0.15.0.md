`ddc` now sees a coding agent's git worktree as a worktree: one finding, with the agent that made it and the project it belongs to, and the artifacts inside it listed under it.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.15.0/DISCLAIMER.md).

- **Worktrees are findings.** A tester saw only the `.venv` inside agent worktrees, while Claude itself, asked to clean, removes whole worktrees. A linked git worktree is now a `git.worktree` finding (group "Git worktrees"), and a folder whose `.git` file names a worktree's missing administrative folder is `git.worktree-orphan`. The main checkout is never one, and neither is a submodule, copied or not.
- **Who made it.** `origin.harness` is `claude-code` when Claude Code's CLI marked the worktree (`CLAUDE_BASE`) or Claude Desktop did (`claude-desktop-worktree`), or it lies under `<project>/.claude/worktrees/`; `codex` when Codex marked it (`codex-thread.json`); otherwise `git`, the person's own. `project.root` is the main checkout, and each finding inside a worktree carries `project.worktree_of`. A worktree copied or moved by hand is marked `linked: false`, with `git worktree repair` as the fix.
- **Read-only in this release.** Both rules are `review` with no removal method: `ddc` lists them and removes nothing of them. The checks a removal needs (clean, no commits of its own, not locked or in use, idle) and `git worktree remove` come in the next releases (story "Worktree findings and provenance").
- **Artifacts inside an agent's worktree are classified as in any project.** A `.venv` or `node_modules` with a lock file inside `~/.codex/worktrees/…` or `~/.cursor/worktrees/…` used to be held at `review` because the folder lies under a hidden folder of the home. Inside a linked worktree it now gets its own rule's class, so `ddc clean --yes` may select it once it is idle for `--min-age` (14 days by default), measured on the worktree's own activity. Outside a linked worktree nothing changed.
- **Report.** `Finding.worktree` (`linked`, `branch`, `detached`, `locked`, `probe: unknown` for now) and `Project.worktree_of` are new optional fields; `schema_version` stays 4.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, or the zip below.

How it was built, decision by decision, is public too: [DeepDriveCleaner-projectstore](https://github.com/SmartAndPoint/DeepDriveCleaner-projectstore).
