The in-use check now sees the file a process really runs, not only the path it was started by. 0.22.4 was not released on its own; this release carries it.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.22.5/DISCLAIMER.md).

- **macOS: in use through a link.** Before a clean, ddc checks that no process of yours runs a program inside the item. On macOS it looked only at the path a process was started by. A program started through a symlink, say a venv's `python` that points into a pyenv version, or `/opt/homebrew/bin/x` that points into its Homebrew keg, was not seen in the folder it really runs from. Now the check also reads the resolved file, as it already did on Linux. So you may see more items skipped as "in use" while such a program runs.
- **macOS: another user's process has a start time.** ddc can now tell when another user's process started, so a process of another user is no longer read as "no process".
- **Groundwork for cleaning old agent builds** (story "Coding agents on Linux"): ddc can read the names of other users' processes, tell whether `/proc` hides other users' processes (`hidepid`), and tell whether the home is on a network file system. Nothing uses them yet.
- Nothing changes in the reports.
- **Native test runs never keep a stale binary (0.22.5).** `scripts/native-windows.sh` and `scripts/native-linux.sh` copy the source tree to a Windows or Linux machine and test it there. They kept each file's own time, so a tree copied after another one could look older than the last build, and cargo kept the old binary: once, four tests failed on a command the copied tree had. Now every file gets the time of the copy.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below. No report schema changed.
