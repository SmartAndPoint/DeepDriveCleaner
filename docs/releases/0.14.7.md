The background scan's notification now names the folders it scanned, and every call of `ddc` the project knows is checked on each commit, along with the commands its output tells you to run.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.14.7/DISCLAIMER.md).

- **The notification keeps your paths.** A background scan of `~/Projects` said "Run `ddc clean` to review.", and `ddc clean` with no path reviews the home. It now says "Run `ddc clean ~/Projects` to review.", as the scan summary has since 0.14.2. The background log now records the text whenever the scan decides to notify, also where nothing shows it (Linux, `--no-notify`), as `notification: …`.
- **A table of calls.** `crates/ddc-cli/tests/cases.json` lists calls of `ddc`, each with the folder it runs in, and what each must do: exit code, the scanned roots, the rules found, text that must or must not appear, the JSON schema. Each runs on a fresh synthetic home. Then every `ddc …` command the output suggests runs too, from the same folder. A suggested clean runs as a dry run and must cover the same roots. With 0.14.1's summary restored, ten cases fail.
- **Every flag has a case.** A test reads clap's command tree, hidden flags included. It fails when a subcommand or an argument is in no case and not in the table's `uncovered` list with a reason. `clean --yes`, `disk free` and `schedule install` are in that list: they change things.
- **An allowlist decides what runs.** The table and the suggestions run only reading commands, `clean` with `--dry-run`, and `disk` under a synthetic system root. Paths must lie inside the temporary root, and anything else is refused by name. On a platform without a command the case expects the refusal (exit 69), not a skip.
- **Before every commit.** The pre-commit hook runs `make cases` after the lint when a staged path is under `crates/` or is `Cargo.toml` or `Cargo.lock` (`scripts/gate-scope.sh staged-cases`). It takes 2 to 9 seconds after the first build. The pre-push tier, CI and the native Linux and Windows runs include it.
- **Linux load limits.** `bench/load-limits-linux.tsv` holds the memory and CPU limits of every load profile on Linux. They were recorded by the nightly `load-linux` job on a GitHub-hosted Ubuntu 24.04 runner. That job now runs every profile at size M and fails over them.
- **Linux tests in WSL.** `scripts/native-linux.sh` runs the Linux leg in a WSL distribution of a Windows machine reached over ssh, as on a Linux machine: `DDC_LINUX_WSL=<distribution>` beside `DDC_LINUX_HOST`. It uses the same docker container and the same folder there. On a Windows machine with WSL, the whole Linux suite passed in WSL and the whole Windows suite natively, with the listed skips.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, or the zip below. No report schema changed. 0.14.5 and 0.14.6 were not released on their own; this release carries them.

How it was built, decision by decision, is public too: [DeepDriveCleaner-projectstore](https://github.com/SmartAndPoint/DeepDriveCleaner-projectstore).
