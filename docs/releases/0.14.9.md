A crash reporter left behind no longer passes for its app: VS Code's caches clean while VS Code is closed.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.14.9/DISCLAIMER.md).

- **"Visual Studio Code is running" when it was not.** Chromium and Electron apps start a crash reporter, `chrome_crashpad_handler`, from inside their bundle, and it can keep running for weeks after the app quits. A tester's Mac had VS Code's running for 21 days, so every VS Code cache was skipped with "Visual Studio Code is running", and Check Again changed nothing. A process named `…crashpad_handler` no longer makes its app count as running. It writes only to its own crash database, and anything it holds open inside a planned item still holds that item back through the in-use check. The same applied to Cursor, Windsurf, Chrome and every other Electron or Chromium app.
- **`native-linux.sh --make <target>`** (0.14.8, not released on its own). It runs a make target (`load`, `load-baseline`, `scaling`) in the same container as the Linux tests, on a Linux machine or in WSL, and copies the measurements back to the local `target/native-linux/load`. `DDC_LINUX_LIMITS=<file>` judges a load run against limits that machine recorded.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, or the zip below. No report schema changed.
