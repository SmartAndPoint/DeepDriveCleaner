ddc now keeps the scan before the last one, so a later release can say what grew between them; each saved report also says who wrote it and when.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.31.0/DISCLAIMER.md).

- **`previous-scan.json`.** When a scan of your usual folders replaces the last one (a `ddc scan`, a scheduled scan, or the re-check `ddc clean` does first), the old report moves to `previous-scan.json` in the data folder, but only if it was a whole, finished scan of those same folders. A scan of one project (`ddc scan ~/Code/app`, as a coding agent runs) or a clean's edit replaces `last-scan.json` and leaves `previous-scan.json` as it was. If the old report cannot be kept, the new one is still saved, with a `ddc: warning:`. Nothing reads it yet: `ddc changes`, coming next, compares the two.
- **Who wrote it, and when.** A saved report now carries `written_by` (`scan`, `background`, `clean-recheck`, `clean`, `clean-items` or `disk-free`), `written_at` (when it was saved), `previous_written_at` (which report `previous-scan.json` holds) and `rules_in_force` (the rules that scan applied, so a new rule's first findings are not read as new growth). All four are optional fields of the scan report, which stays at schema 8.
- Two of your usual scans in a row keep the first; a cancelled scan is never kept. The data folder now holds a second report of about the same size as the first.

**Report schemas.** The scan report stays at 8 and gains four optional fields. Space 1, clean 10, journal 10, progress 8 are unchanged.
