A Windows step on the way to Windows support: how ddc runs a tool such as `uv` or `git` there. Windows is still not supported, so nothing of this runs outside the tests yet. On macOS and Linux one thing changes: a relative folder in the tool search is now skipped.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.30.1/DISCLAIMER.md).

- **Windows: each tool runs in a box of its own.** When ddc runs a tool, for a clean (`uv cache clean`) or to ask git about a worktree, the tool now runs in its own Windows Job Object. If it runs too long, or you press Ctrl-C or close the window, ddc ends the job, which ends the tool and everything it started. A tool that crashes ends, and does not hold the item behind an error dialog.
- **Windows: no tool from the current folder.** A tool starts in the Windows system folder, and Windows is told not to look for programs in the current folder. So a program lying in the folder you started ddc from (a cloned repository, say) is never run by mistake.
- **Windows: which files are tools.** ddc looks for `name.exe`, then `name.cmd`, then `name.bat`, and only in folders given by a full path. It never uses `PATHEXT`, and never runs a file with no extension.
- **Every OS: no relative folder in the tool search.** On Windows `/usr/bin` means a folder at the root of the current drive, which any user can create. ddc now drops every search folder that is not a full path. On macOS and Linux all of them already are, so nothing changes there in practice.

**Report schemas.** None change.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
