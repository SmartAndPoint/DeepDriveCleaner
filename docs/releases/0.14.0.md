`ddc disk agents` now shows what each Claude Code session keeps: its transcript, its checkpoints and its temporary folder outside the home, with whether the session is live.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.14.0/DISCLAIMER.md).

- **Per-session footprint.** With sizes, `ddc disk agents` measures Claude Code's temporary folder (`/private/tmp/claude-<uid>` on macOS, under `CLAUDE_CODE_TMPDIR` when that is set), which can hold more than everything Claude Code keeps in the home folder. Each session gets a row: its transcript and companions, its checkpoints in `~/.claude/file-history`, its temporary folder (scratchpad, tasks, images) and the total, with whether it is live, not live or unknown, decided as the cleanup's session check decides it. A session whose transcript is gone still gets a row for its temporary folder. The text shows the ten largest sessions and the rest in one line; `--json` lists them all. A live session's files are only described; a row that is not live names its temporary folder. The command still reads names, sizes and the session records' named fields, never a transcript's content, and removes nothing. `--no-sizes` measures none of it.
- **Tests.** The marked-folder removal test skips where the platform is not supported.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, or the zip below. The agents report stays schema 1: `footprints` and `temp_root` under Claude Code's `sessions` are new and optional, and the harness bytes are still the home folder's alone. The app does not show the footprint yet.

How it was built, decision by decision, is public too: [DeepDriveCleaner-projectstore](https://github.com/SmartAndPoint/DeepDriveCleaner-projectstore).
