Coding agents learn the two commands they got in 0.37.0, and `ddc agent skill install` puts that guidance where Claude Code, Codex, opencode, Gemini CLI and Qwen Code read it. On Linux, a home on NFS is scanned and cleaned as the user's own even when the server squashes their ids, and a file still open there no longer fails a clean.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.38.0/DISCLAIMER.md).

**The guidance for coding agents: `agents/`**

- The Claude Code skill and the `AGENTS.md` snippet now say when to ask ddc: at the start and the end of a session in a worktree, before an install into a new worktree, on `ENOSPC`, and when you ask the agent to clean up after itself.
- The agent asks `ddc changes --json` before it scans, since a scan replaces your latest report. For its own project it asks `ddc agent footprint --json`.
- The one removal that is the agent's is `ddc agent clean`: the safe items inside its project, and only while you allow it in DeepDriveCleaner's settings. It shows you the `ddc clean --items -` command for the rest, and never runs it. A worktree is never the agent's to remove.
- When ddc is missing, the agent proposes the cask or the install script, and runs it only after you say yes.
- The skill's `allowed-tools` lists only commands that read: `ddc changes`, `ddc agent status`, `ddc agent footprint`, `ddc agent clean --dry-run` and `ddc rules`, under both names. Everything else still asks you.

**Installing it: `ddc agent skill install` and `ddc agent skill status`**

- `ddc agent skill install` writes the skill from the copy built into this ddc. It goes into `~/.claude/skills/ddc` for Claude Code and into `~/.agents/skills/ddc`, which Codex, opencode, Gemini CLI and Qwen Code read; with `--project DIR`, into that project's two folders. `--family claude-code` or `--family agents` writes only one. With `--agents-md FILE` it also writes ddc's block into that `AGENTS.md`.
- It lists the files and asks first, and it deletes nothing. Without a terminal it needs `--approved`, which an agent passes only after you said yes in the chat.
- It plans every folder before it asks, and a refusal in one writes none. It writes only into a skill folder it installed itself and nobody edited since. It tells its own copy by a `.ddc-skill` file; `--replace` writes over another copy, never over a symbolic link.
- In `AGENTS.md` it replaces only the block between `<!-- ddc:begin -->` and `<!-- ddc:end -->` and keeps the rest of the file and its permissions. It refuses a missing or second marker, and CRLF line endings.
- `ddc agent skill status [--json]` says, for each folder and its `family`, whether it is this ddc's, an older one's, edited, or not installed by ddc (`docs/skill.schema.json`). Neither command takes a lock or writes the journal.
- A scan never offers to remove anything under `~/.claude/skills` or `~/.agents/skills` (the new rule `agent.shared-skills-sealed`).

**The app's toggle for coding agents.** `ddc settings set` takes the app's approval as `--from-app` now. The app ships its own ddc, so nothing changes for you. If you upgrade with Homebrew while the app runs, quit and open it once before you switch the setting again.

**Linux: network and encrypted homes**

- **Squashed ids.** When an NFS server shows your files under another owner, a scan says so once and names that volume. Your own files there are planned and removed as yours. Another user's files stay `foreign-owner` and are never selected.
- **Open files.** A file still open on an NFS home is left as a "silly rename" (`.nfs…`) until it is closed. A clean now removes the rest and names that file, instead of failing the item. A worktree whose finding holds such a file is not selected (`held-open`).
- **eCryptfs.** `~/.Private` and `~/.ecryptfs` are never walked or removed. `ddc changes` no longer counts them as "behind a macOS prompt".

**Windows (not released yet).** The port gained its own rules (Temp, WSL's disks and NuGet), its cloud folders (OneDrive, Dropbox, Box, iCloudDrive) are protected and never walked, and conda and git are found where Windows installs them. Windows builds still refuse to scan or clean until the port is done.

**Fixes.** `cargo deny` failed on two new advisories that mark chrono and humantime as unmaintained; neither is a vulnerability, and both are allowed with their reasons until humantime moves to jiff.

**Report schemas.** New: skill 1 (`docs/skill.schema.json`). Scan 10 (a volume's `id_mapping` and the `held-open` reason), clean, footprint and progress gained the NFS fields. Settings, agents, changes and docker are unchanged.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below. If you upgrade with Homebrew while the app is quit, open it once so it registers its scheduled scan again.
