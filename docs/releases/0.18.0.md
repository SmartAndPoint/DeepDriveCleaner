`ddc` now checks an agent's worktree the way a removal will need: clean down to its ignored files, no commits of its own, not locked or in use, idle. It still removes no worktree. 0.17.5 and 0.17.6 were not released on their own; this release carries them.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.18.0/DISCLAIMER.md).

- **The six conditions.** A worktree a coding agent made (Claude Code's marker or `.claude/worktrees/`) is checked in order, stopping at the first that fails: unlocked and not in use, idle for `--worktree-min-age` (2 days by default, measured on the worktree's own activity), no initialized submodule, clean including ignored files, and no commit that only it holds. Each ignored file must be an artifact `ddc` would remove anyway or a byte-identical copy of the main checkout's file (`.env` copied by `.worktreeinclude`); files git was told to stop checking (`skip-worktree`, `assume-unchanged`) keep the worktree too. The result is in `worktree` in the report, with a hint naming the first failed condition. A worktree of your own, or a Codex one for now, is not probed.
- **Not selected yet.** A worktree that passes is `rebuildable`, but it is not selected and counts in no "can free" total: removing it through `git worktree remove` comes in the next release.
- **git is asked carefully.** Every git command runs with no optional locks, no repository helpers (fsmonitor, hooks, pager) and a 30-second timeout, and drops any `GIT_*` variable it inherits, so `ddc` run from a git hook cannot act on another repository. On macOS `ddc` never runs `/usr/bin/git`, which offers to install the developer tools when they are missing; with no other git the result is "unknown" and the worktree stays as it is. A git that fails, hangs or prints something unexpected leaves the worktree untouched.
- **`--worktree-min-age <days>`** on `ddc scan` and `ddc clean`.
- **Ctrl-C reaches every git probe** running in parallel, not only the last one started.
- **Release facts.** The CLI and product pages of ddc.sh and deepdrivecleaner.app link the 0.17.4 archives for macOS and Linux, its `SHA256SUMS` and its release page. `llms.txt` names 0.17.4 too.

- **CI.** The Install workflow's `cargo binstall` check passes the workflow's token to the GitHub API. Without it the API refused the runner (403), and binstall gave up before its retry.
- **Windows: the directory reader (0.17.5).** A folder is read through its own handle, many entries per call, past the 260-character path limit. A link (a symlink, a junction, any name surrogate) is listed as a link and never followed. A volume mounted into a folder is a boundary: the scan does not enter it. On a file system without file ids (FAT, exFAT) the reader falls back to a slower listing that opens each entry for its id, and still tells links apart.
- **Windows: hard links counted once (0.17.5).** A Windows folder listing does not carry a file's link count. So a file with allocated bytes goes into the scan's hard-link table, and a file that several names share counts once, as on macOS and Linux. pnpm and uv store their packages this way.
