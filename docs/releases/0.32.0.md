A clean from the terminal now updates the saved report, as the app's clean already did, so the app and `ddc space` see the disk as the clean left it.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.32.0/DISCLAIMER.md).

- **`ddc clean` edits `last-scan.json` after cleaning.** Before, a terminal `ddc clean` saved only the re-check it does first, so the report still listed what it then removed. Now it edits that report by what it did: removed items leave and the totals drop by their size, a trashed item's bytes move to the Trash finding of its disk, a tool's cache is measured again, and each disk the clean touched takes the free space read at the end, with the time in `read_at`. The report says `written_by: clean`. It is saved after a Ctrl-C too, with what was done before it; if the save fails, ddc says so with a `ddc: warning:` and the clean still counts.
- **`ddc space` after a terminal clean.** The used-space check now compares from the free space that clean read, as it does after the app's clean, so space freed by a clean in the terminal is not read as a change since the scan.
- A dry run, a declined plan and "Nothing selected" save only the re-check, as before. `previous-scan.json` keeps the report from before the clean, as in 0.31.0.

**Report schemas.** None change in shape; the descriptions of `read_at` (scan 8) and of the `clean` baseline (space 1) now name both cleans. Clean 10, journal 10, progress 8 are unchanged.
