The Windows port goes on: paths are compared the way Windows compares them. Nothing changes on macOS or Linux. 0.16.5, a test fix, was not released on its own; this release carries it.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.16.6/DISCLAIMER.md).

- **One canonical path.** Every part of ddc resolves a path through one call. On Windows it gives `C:\…`, not the `\\?\C:\…` form Windows' own call returns, so an exclude, a skip or a root compares with what the scan finds. A name that the plain form cannot spell (a trailing dot or space, a device name such as `NUL`) keeps the long form and is never matched by mistake.
- **Windows paths compared without case.** The rule catalog and the protected folders compare Windows paths by one key that ignores case and treats `/` and `\` alike, as Windows does. On macOS and Linux a path is compared as it is, as before.
- Windows is still unsupported: `ddc` there runs only `--version`, `--help` and `rules` (story "Windows scanner and rule catalog", step 2 of 15).
- **0.16.5.** The popover's scan count test waited for the first of three walk events' file counts, while the popover keeps the largest; it now waits for the largest count.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, or the zip below. Nothing you can see changed on macOS or Linux.
