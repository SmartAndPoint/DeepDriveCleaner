On Linux, ZFS child datasets inside a scan root are now counted, and their snapshots never are.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.29.0/DISCLAIMER.md).

- **Linux: ZFS child datasets are counted.** On a ZFS home (Ubuntu's ZFS install, Proxmox) a dataset below the scan root is its own mount, so the scan stopped there as at another filesystem. ddc now enters a child dataset of the same pool when it is mounted where it inherits its mount point: `pool/home/you/work` at `~/work`. A dataset with its own `mountpoint=` elsewhere, and a bind mount of a dataset, stay another filesystem. Each dataset is read beneath its own anchor, so nothing outside it is crossed.
- **`.zfs` is never entered.** The hidden snapshot folder at a dataset's root is listed as `snapshot`, never counted, and the scan never mounts a snapshot by looking into it.
- **A dataset is never removed.** A finding that holds a dataset, or is one, is listed as `holds-subvolume` and not planned, as for btrfs subvolumes. An item inside a dataset is cleaned as usual; its move to the Trash goes into that dataset's own `.Trash-<uid>`.
- **A ZFS clone** is an ordinary dataset and is counted in full, though it shares blocks with the snapshot it came from.
- `ddc du` now counts child datasets below a root, which `du -x` does not.
- Nothing changes on macOS or Windows. No report schema changed.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
