On Linux, a file on a btrfs subvolume or a ZFS dataset now keeps the same identity after a remount or a reboot.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.30.0/DISCLAIMER.md).

- **Linux: stable identities on btrfs and ZFS.** The kernel gives every btrfs subvolume and every ZFS dataset an anonymous device number, and that number can change at the next mount. ddc compares a file's device and inode to tell that it is still the file it scanned, so after a remount a saved scan or a keep record no longer matched, and the clean refused the items as changed. On btrfs and ZFS ddc now uses the filesystem's own id (`f_fsid`), which stays the same across mounts. Everything that compares identities uses it: the scan, the checks before a removal, the Trash, and the in-use check that reads `/proc`.
- **A file held open inside a subvolume or a dataset counts as in use**, with the same identity the scan wrote.
- **Scan report schema 8.** On btrfs and ZFS, `dev` in a report is now the folded filesystem id. Nothing else in the report changed. A scan saved by an older ddc on such a home shows its items as changed since the scan, once; scan again.
- Nothing changes on macOS or Windows, and on other Linux filesystems `dev` stays what it was.
