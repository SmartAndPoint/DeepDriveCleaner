On Linux, btrfs subvolumes are now counted and btrfs snapshots never are. 0.26.3 was not released on its own; this release carries it.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.27.0/DISCLAIMER.md).

- **Linux: btrfs subvolumes are counted.** On a btrfs home (Fedora's default) a subvolume inside a scan root, made with `btrfs subvolume create` or by a tool, was skipped as another filesystem and not counted. ddc now enters a plain subvolume on the same mount, after asking the kernel what it is (`BTRFS_IOC_GET_SUBVOL_INFO`, no root needed). A second btrfs disk mounted inside is still another filesystem.
- **Snapshots are never counted.** A btrfs snapshot (Snapper, Timeshift, `btrfs subvolume snapshot`, read-only or writable) and a `btrfs receive` backup are listed with the new reason `snapshot`, and never counted or cleaned. A subvolume that was once a snapshot stays one: a home restored from a Timeshift snapshot, or a rootless Podman layer, counts zero.
- **A subvolume is never removed.** A finding that holds a subvolume, or is one, counts its bytes but is not planned: the inner subvolume is listed as `holds-subvolume`, and the finding reads incomplete. The guard refuses it again before any rename. Items inside a subvolume are cleaned as usual; moving one to the Trash gives `trash-crosses-filesystem`, and `--permanent` removes it.
- `ddc du` now counts subvolumes below a root, which `du -x` does not.
- Nothing changes on macOS or Windows except the report's version.
- **Windows: the in-use check reads your processes (0.26.3).** Before a clean, ddc skips an item that one of your programs uses: its program file, its working folder, an argument or its `VIRTUAL_ENV` or `CONDA_PREFIX` lies inside the item. On Windows ddc now reads all of this for each of your processes, the same as it does on Linux. Paths are compared without regard to upper or lower case or to `/` and `\`. A path on a network share named in a command line is never opened.
- **What it cannot read, it says.** A process ddc cannot read in full is counted, as on macOS and Linux. That includes a protected one and a 32-bit one, whose working folder Windows keeps where ddc does not read it yet. Programs loaded as modules (a DLL, a `.pyd` or `.node` file inside a folder) come in the next step.

**Report schema.** The scan report moves to schema 7, for the reasons `snapshot` and `holds-subvolume`. Update the app and the CLI together.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
