The command-line tool runs on Linux, old builds of the VS Code and Cursor servers are found, cleaning Hugging Face downloads no longer signs you out, and another user's files are never cleaned.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.13.11/DISCLAIMER.md).

- **Linux.** `deepdrivecleaner` (and `ddc`) now runs on x86_64 and aarch64 Linux as one static binary, installed by the script or from the archives below. `scan`, `clean`, `keep`, `rules` and `du` work there with the Linux catalog: the XDG caches, JetBrains, VS Code, Cursor and Windsurf, the coding agents, the browsers, rootless Docker and Docker Desktop, and the freedesktop Trash. Sizes match `du`, folders' own blocks included. Before anything is removed, the same checks as on a Mac run, with the Linux limits of the in-use check stated in the safety model: a process ddc cannot read in full is counted in the dry run and the clean report. `/var/lib/docker` and `/var/lib/containers` are never walked. `disk`, `disk agents`, Homebrew, `schedule` and notifications stay macOS's.
- **Old editor servers.** VS Code and Cursor install a server build on every machine they reach over ssh, about 200 MB each, and leave interrupted installs behind. The IDE caches now find the builds and `.staging` leftovers under `~/.vscode-server` and `~/.cursor-server`; the build the editor used last stays, and a build a connected editor runs is never removed.
- **Hugging Face keeps its token.** The ML models rule used to take all of `~/.cache/huggingface`, the sign-in token with it. It now finds `hub`, `xet` and `datasets`, the downloads, and leaves `token` and `stored_tokens` where they are.
- **Another user's files stay.** A finding that holds files or folders of another user, as a container running as root leaves in a project, is listed as "another user's", never selected, and skipped before anything is moved if a plan names it.
- **Names that are not UTF-8.** A report used to fail on one. Such a path is now written with � for the bytes that are not text, and the scan and clean reports count them in `lossy_paths`.

**Upgrading.** The app offers this version itself: Update and Relaunch, or Settings → General → **Check Now**. `brew upgrade --cask deepdrivecleaner` and the zip below work too. Report formats changed since 0.12.1: scan schema 4 and progress schema 4 (the reason `foreign-owner`), clean schema 6 and journal schema 6 (the skip reason `foreign-owner`), the optional `lossy_paths` and `unreadable_processes`, and rules schema 2 (`platform`, the catalog's OS). Update the app and the CLI together; a report from another version is named as such and not read. Scripts that read the reports need the new versions.

How it was built, decision by decision, is public too: [DeepDriveCleaner-projectstore](https://github.com/SmartAndPoint/DeepDriveCleaner-projectstore).
