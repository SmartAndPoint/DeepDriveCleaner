A small Windows step on the way to Windows support. Windows is still not supported, so nothing of this runs outside the tests yet; on macOS and Linux nothing changes.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.26.1/DISCLAIMER.md).

- **Windows: a read-only `.ddc-keep` is removed.** `ddc keep remove` deletes the marker even when it is marked read-only, as Windows' own delete does. Where a volume does not take that request, ddc clears the mark on the same file, deletes it, and puts the mark back if the delete still fails.
- **Windows: read-only files before a delete retry.** When removing a folder fails with "access denied", ddc tries once more. Before that retry it now clears the read-only mark of the files inside, on FAT and exFAT volumes only, and never through a link. **This does not work yet on FAT or exFAT:** those volumes do not give ddc the file ids it needs, so ddc cannot open a folder there at all today. What ddc does with such volumes, most likely refuse them with a clear message, is decided before Windows support is switched on.

**Report schemas.** None change.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`, the app's Check Now, the install script, or the zip below.
