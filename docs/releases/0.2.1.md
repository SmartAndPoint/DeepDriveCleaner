Two fixes from the first day of 0.2.0.

> **DeepDriveCleaner deletes files.** It can remove almost anything it is told to, by you or by an agent acting for you. Use it at your own risk: nobody who made it is responsible for what it removes. Read [DISCLAIMER.md](https://github.com/SmartAndPoint/DeepDriveCleaner/blob/v0.2.1/DISCLAIMER.md).

- **The Review window can be found again.** While the Review window, Settings or About is open, the app is in the Dock and in Cmd-Tab, with its own menu bar: ⌘W closes the window, ⌘Q quits, and copy and paste work in the search field. When the last window closes, the app lives in the menu bar only again and the app you were using comes back to the front.
- **A clean no longer waits on a cache that a running program uses.** In 0.2.0 a clean could sit for ten minutes on `uv cache clean` while `uv run` processes held uv's cache lock. Now a file that a running process holds open inside a cache or a project folder counts as use: the item is skipped with the name of the program, and the clean goes on. A program that holds a file only for a moment, such as a Spotlight worker, does not block it, and the check runs again right before a tool's own clean command. A move to the Trash is not affected.
- **Docker and Podman images are pruned while Docker or Podman runs.** 0.2.0 skipped them as in use, because their daemon works inside its own folder. Their prune commands decide for themselves what is in use.

**Upgrading.** `brew upgrade --cask deepdrivecleaner`. The upgrade quits the app; it opens again at your next login if Open at login is on, or when you open it. Do not upgrade while the app is cleaning.

How it was built, decision by decision, is public too: [DeepDriveCleaner-projectstore](https://github.com/SmartAndPoint/DeepDriveCleaner-projectstore).
