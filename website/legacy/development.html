Development manual

An agent-first application, developed with ProjectStore.

This project is both a Mac utility and a worked example of development with humans and agents. Contributions made with your own agent are welcome.

People set goals and approve decisions. Agents help plan, implement, challenge proposals and review changes. The shared vault keeps the context available across contributors and sessions.

How a change is developed

Code and project memory are separate repositories. Start with the vault, check for overlapping work and follow the project's gates.

  1. ArtifactWrite a story with acceptance criteria. Record significant decisions in an ADR; add a spec when needed.
  2. CriticA fresh-context critic checks the proposal before implementation. A human approves the artifact.
  3. PlannerRead the code map and existing implementation to decide where the change belongs.
  4. ImplementationBuild the agreed behavior and run checks relevant to the change.
  5. ReviewerAn independent reviewer compares the diff with the acceptance criteria. Record evidence before closing the story.

Contributor setup

Full contributing guide ↗

Requirements: Node.js 20 or later. Run setup in a regular terminal, outside an agent session. Clone the two repositories side by side.

1.Clone and bind the project

Terminal
git clone https://github.com/SmartAndPoint/DeepDriveCleaner.git
git clone https://github.com/SmartAndPoint/DeepDriveCleaner-projectstore.git
cd DeepDriveCleaner
npx projectstore setup --vault ../DeepDriveCleaner-projectstore

2.Start Claude Code or Codex

Start your agent inside the DeepDriveCleaner code directory. Give it this orientation prompt before asking it to change code:

Prompt for your agent
Where are we?

Read AGENTS.md and the bound ProjectStore vault. Summarize active epics, open stories and relevant decisions. Help me choose a small contribution and check for overlapping work. Follow the project's artifact, critic, planner and reviewer gates. Propose the next step before changing code.

Review the interface designs in Claude Artifact before proposing UI changes. ↗

3.Keep the change reviewable

Agree on a story, keep the diff focused and attach relevant validation. Coordinate code and vault pull requests so the reviewer can follow the intent and implementation.

make check
Rust changes: formatting, clippy and tests.
make app-test
App logic changes: DDCKit tests.
